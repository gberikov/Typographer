## 1. [P1] Преждевременное завершение защищённой зоны

**Где:** [MarkupScanner.cs](../../../src/Typographer/Internal/MarkupScanner.cs),
`IndexOfClosingTag`, строка 158.

**Воспроизведение, HTML:**

```csharp
// Вход
"<pre><!-- </pre> -->a - b</pre>"
// Фактический результат
"<pre><!-- </pre> -->a\u00A0— b</pre>"

// Вход
"<code>outer <code>inner</code> a - b</code>"
// Фактический результат
"<code>outer <code>inner</code> a\u00A0— b</code>"
```

**Ожидается:** оба входа возвращаются без изменения символов.

**Причина:** поиск берёт первое текстовое совпадение закрывающего тега,
не учитывая комментарии и вложенность. Хвост защищённой зоны попадает в `Scan`.

**Направление исправления:** искать структурную границу защищённого элемента;
для элементов с обычным HTML-содержимым учитывать вложенность, комментарии
и значения атрибутов. Для `script`, `style` и `textarea` сохранить соответствующие
режимы чтения содержимого, не переносить на них механически правила вложенности `code`.

**Приёмка:** точное равенство входа и выхода для обоих примеров, закрывающего тега
в значении атрибута внутри `pre`, вложенных одноимённых элементов и незакрытой зоны.
Существующие проверки регистра и границы имени закрывающего тега остаются зелёными.

## 2. [P1] CDATA завершается на первом символе `>`

**Где:** [MarkupScanner.cs](../../../src/Typographer/Internal/MarkupScanner.cs),
`TryRead` / `ReadTagEnd`, строки 68–70 и 119.

**Воспроизведение, HTML:**

```csharp
// Вход
"<![CDATA[ x > a - b ]]>"
// Фактический результат
"<![CDATA[ x > a\u00A0— b\u00A0]]>"
```

**Ожидается:** исходная строка целиком, включая содержимое CDATA.

**Причина:** CDATA распознаётся как обычная разметка, заканчивающаяся на `>`;
оставшаяся часть становится текстовым узлом.

**Направление исправления:** распознавать начало CDATA до общего разбора тега
и сохранять сегмент до `]]>` включительно; при отсутствии терминатора сохранять
оставшийся вход. Это требование уже есть в §5.1 спецификации.

**Приёмка:** CDATA с `>`, кавычками, дефисами, похожими на теги фрагментами
и отсутствующим терминатором проходит без изменений; обычный текст после
закрытого CDATA продолжает обрабатываться.

## 3. [P2] Декодирование типографских сущностей не подключено к конвейеру

**Где:** [HtmlTypograf.cs](../../../src/Typographer/HtmlTypograf.cs), `Run`, строка 81;
[EntityTable.cs](../../../src/Typographer/Internal/EntityTable.cs), `TryDecode`.

**Воспроизведение:**

```csharp
var typograf = new HtmlTypograf(new HtmlOptions { Entities = EntityMode.Named });
string once = typograf.Process("текст,- слово");
// once: "текст,&nbsp;&mdash; слово"
string twice = typograf.Process(once);
// twice: "текст, &nbsp;&mdash; слово"
```

То же добавление пробела на втором прогоне воспроизводится в `Numeric` и `Mixed`.
Кроме того, вход `"слово&nbsp;- слово &mdash; &laquo;текст&raquo;"` остаётся
неизменным во всех четырёх режимах вывода сущностей.

**Ожидается:** `once == twice`; существующие типографские сущности участвуют
в правилах как соответствующие символы и выводятся согласно `EntityMode`.
Например, при `Rules = RuleSet.None` и `Entities = EntityMode.Symbols`
вход `"&mdash;"` должен дать `"—"`.

**Причина:** `TryDecode` проверяется отдельными unit-тестами, но производственный
конвейер его не вызывает. Сканер видит `&nbsp;` как последовательность символов,
а не как пробел.

**Направление исправления:** декодировать типографские сущности внутри текстовых
сегментов перед `Scan`. Защищённые зоны и атрибуты сохранять буквально.
`&amp;`, `&lt;`, `&gt;`, `&quot;` и остальные нетипографские сущности не декодировать
в рамках этой правки; текст не должен становиться разметкой.

**Приёмка:** идемпотентность приведённого примера для всех режимов; преобразование
именных, десятичных и шестнадцатеричных типографских сущностей в выбранный режим;
сохранность нетипографских сущностей, тегов, атрибутов и защищённых зон.

## 4. [P2] `UseP` создаёт абзацы по границам технических фрагментов

**Где:** [HtmlTypograf.cs](../../../src/Typographer/HtmlTypograf.cs), строка 83;
[LayoutWriter.cs](../../../src/Typographer/Internal/LayoutWriter.cs), строки 52–58.

**Воспроизведение A:** `Rules = RuleSet.None`, `UseP = true`.

```csharp
// Вход
"Текст <b>жирный</b> конец"
// Фактический результат
"<p>Текст </p><b><p>жирный</p></b><p> конец</p>"
// Ожидается
"<p>Текст <b>жирный</b> конец</p>"
```

**Воспроизведение B:** правила по умолчанию, `UseP = true`, `MaxNobr = 2`.

```csharp
// Вход
"Первый в доме конец"
// Фактический результат
"<p>Первый </p><nobr>в\u00A0доме</nobr><p> конец</p>"
// Ожидается
"<p>Первый <nobr>в\u00A0доме</nobr> конец</p>"
```

**Причина:** компоновка запускается отдельно на каждом текстовом узле, а
`WriteWithNobr` повторно запускает формирование абзацев на кусках вокруг цепочек.
Граница буфера ошибочно становится границей абзаца.

**Направление исправления:** сохранять состояние формирования абзаца через
строчные теги и `nobr`-группы либо формировать абзацы на уровне, где видна вся
их структура. Создание `nobr` не должно закрывать текущий `p`.

**Приёмка:** оба ожидаемых результата; несколько строчных тегов и несколько
`nobr`-групп в одном абзаце; сочетание `UseP`, `UseBr`, `MaxNobr`; разделение
абзацев по `\n\n` и `\r\n\r\n`.

Ошибка возникает на первом прогоне. Документированное исключение из
идемпотентности для повторного применения опций разметки её не покрывает.

## 5. [P2] Граница HTML-абзаца не обновляет контекст сканера

**Где:** [HtmlTypograf.cs](../../../src/Typographer/HtmlTypograf.cs), строки 70–73;
[TextScanner.cs](../../../src/Typographer/Internal/TextScanner.cs), `ScanState`.

**Воспроизведение, HTML:**

```csharp
// Вход
"<p>Первый</p><p>\"Второй\"</p>"
// Фактический результат
"<p>Первый</p><p>»Второй»</p>"
// Ожидается
"<p>Первый</p><p>«Второй»</p>"
```

**Причина:** разметка копируется без обновления контекста; первая кавычка второго
абзаца видит последнюю букву первого абзаца.

**Направление исправления:** различать границы блоков/переносы и строчную
разметку. Обновлять контекст начала строки или абзаца без вставки лишних
символов в исходную разметку. Не сбрасывать всё состояние на каждом теге:
это вернёт уже исправленные ошибки кавычек вокруг ссылок.

**Приёмка:** пример выше, прямая речь в начале следующего `p`, контекст после `br`;
существующие случаи кавычек вокруг ссылки и `<b>А</b>- б` остаются корректными.

## 6. [P2] Готовые кавычки не участвуют в учёте вложенности

**Где:** [TextScanner.cs](../../../src/Typographer/Internal/TextScanner.cs),
ветка `quotes && c == '"'`, строка 61;
[QuoteStack.cs](../../../src/Typographer/Internal/QuoteStack.cs).

**Воспроизведение, обычный текст:**

```csharp
// Вход
"«текст \"вложенный\" текст»"
// Фактический результат
"«текст «вложенный» текст»"
// Ожидается
"«текст „вложенный“ текст»"
```

**Причина:** готовые типографские кавычки записываются в вывод, но не обновляют
стек. Прямые кавычки внутри существующей пары считаются первым уровнем.

**Направление исправления:** учитывать уже оформленные пары при определении
вложенности; учитывать неоднозначность символов, используемых также как апострофы.
После исправления пункта 3 это должно работать и для декодированных сущностей.

**Приёмка:** смешанные прямые и готовые кавычки на двух и трёх уровнях в обоих
API; сохранность полностью оформленного текста, апострофов и штрихов после чисел;
идемпотентность результата.

## 7. [P2] Инициал в конце ввода или перед пунктуацией не связывается с фамилией

**Где:** [WordBinder.cs](../../../src/Typographer/Internal/WordBinder.cs),
строки 47–74.

**Воспроизведение, обычный текст:**

```csharp
// Вход и фактический результат
"Пушкин А."
"Пушкин А., автор"
// Ожидается соответственно
"Пушкин\u00A0А."
"Пушкин\u00A0А., автор"
```

**Причина:** распознавание инициала запускается только при встрече обычного
пробела после токена. Конец ввода не завершает обработку токена, а пунктуация
сбрасывает его состояние до привязки.

**Направление исправления:** завершать обработку токена на необходимых границах
и в конце ввода; отдельно решать привязку к предыдущему и следующему слову,
не добавляя отсутствующий пробел в конце строки.

**Приёмка:** оба примера, фамилия с одним и двумя инициалами, инициал перед
переводом строки и закрывающей кавычкой; существующие тесты `А. С. Пушкин`
и `Пушкин А. С.` остаются зелёными.

## 8. [P2] Лимит результата применяется к промежуточным буферам

**Где:** [TextTypograf.cs](../../../src/Typographer/TextTypograf.cs), строки 25 и 49;
[HtmlTypograf.cs](../../../src/Typographer/HtmlTypograf.cs), строки 76–78;
[CharBuffer.cs](../../../src/Typographer/Internal/CharBuffer.cs), `EnsureCapacity`.

**Воспроизведение:**

```csharp
var typograf = new TextTypograf(new TextOptions { MaxOutputLength = 1 });
typograf.Process("...");
// Фактически: OutputTooLargeException.
// Ожидается: "…", длина результата равна 1.
```

**Причина:** сканер временно записывает две точки перед свёрткой многоточия;
лимит конечного результата уже применяется к этому промежуточному состоянию.
В HTML-конвейере промежуточные буферы получают тот же лимит.

**Направление исправления:** отделить ограничение длины окончательного результата
от размера временного представления. Сохранить проверку фактического итогового
вывода, включая HTML-разметку и расширение символов при кодировании сущностей.

**Приёмка:** сокращающийся вход с итоговой длиной ровно на лимите проходит;
итоговый результат сверх лимита бросает `OutputTooLargeException`; проверить
обе точки входа, обе перегрузки `Process`, все режимы сущностей и несколько
HTML-сегментов.

**Уточнение к предыдущему handoff:** утверждение в
[документе для плана 2](2026-09-08-input-for-plan-2.md) о том, что суммарный
HTML-результат может обойти лимит, не подтвердилось на проверенном коммите.
Финальный `buffer` также имеет `MaxOutputLength` и контролирует весь вывод.
Вызов с `Rules = RuleSet.None`, лимитом `10` и входом `<b>a</b><i>b</i>`
корректно бросает исключение. Подтверждённая проблема — преждевременное
срабатывание лимита на промежуточном результате.

## 9. [P2] Повторный пробел меняет распознавание дефиса перед числом

**Где:** [TextScanner.cs](../../../src/Typographer/Internal/TextScanner.cs),
условие `dashMain`, строка 119, и `IsNumberAhead`.

**Воспроизведение, обычный текст:**

```csharp
// Вход с одним пробелом справа от дефиса: сохраняется
"текст - 5"
// Вход с двумя пробелами справа от дефиса
"текст -  5"
// Фактический результат второго входа
"текст\u00A0— 5"
// Ожидается после удаления повторного пробела
"текст - 5"
```

**Причина:** `IsNumberAhead` проверяет символ на фиксированной позиции `i + 2`.
При двух пробелах там ещё пробел; позже `DelRepeatSpace` его удаляет, но решение
о замене дефиса уже принято.

**Направление исправления:** проверять правый контекст с учётом пробелов,
удаляемых включёнными правилами. Сохранить различие между тире между словами
и дефисом перед числом и линейную сложность обхода.

**Приёмка:** один, два и несколько пробелов перед числом дают согласованный
результат при `Default`; отдельно проверить сочетания включённых/выключенных
`DelRepeatSpace` и `Dash.Main`, отрицательные числа и обычное тире между словами.

## Порядок работы и общая приёмка

1. Исправить защиту разметки: пункты 1–2.
2. Подключить декодирование и исправить контекст кавычек: пункты 3, 5–6.
3. Исправить компоновку абзацев: пункт 4.
4. Исправить обработку инициалов, лимита и правого контекста: пункты 7–9.

Для каждого пункта сначала добавить падающий регрессионный тест на приведённый
пример, затем исправить поведение. Размещать проверки в существующих группах
`Internal`, `Rules`, `PipelineTests` и `Guarantees` по смыслу. Проверки только
идемпотентности недостаточны: неверный результат тоже может быть идемпотентным,
поэтому нужны точные ожидаемые строки.

После изменений выполнить:

```powershell
rtk dotnet build Typographer.slnx
rtk dotnet test tests/Typographer.Tests
```

В итоговом отчёте перечислить закрытые пункты, новые тесты и результаты проверок.
Сохранить побайтовую целостность защищённых зон, переносы строк, поведение
`IBufferWriter<char>`, возврат исходного экземпляра строки при отсутствии правок
и документированную идемпотентность правил. Если исправление существенно меняет
количество проходов или буферов, дополнительно проверить влияние на производительность.
