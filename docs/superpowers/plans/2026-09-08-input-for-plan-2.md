# Что план 1 передаёт плану 2

Собрано из финального ревью ветки `feature/core` и журнала исполнения плана 1.
Всё, что здесь перечислено, проверено на работающем коде, а не предположено.

## Уже сделано в плане 1 — на это можно опираться

**Левый контекст читается из буфера.** Четыре разрыва идемпотентности подряд имели
одну причину: правило фазы `Scan` принимало решение по исходной строке, а
редактировало буфер, и потому не видело правок соседних правил. Двенадцать правил
дали четыре стыка; сто семь дали бы десятки, и перечислить их тестами нельзя —
пар квадратично много. Инвариант введён: левый контекст берётся только из буфера,
правый — из исходной строки. Новые правила обязаны его соблюдать.

Побочное следствие: предикат знаков препинания описывает класс символов, а не их
сырые формы. Добавляя правило, которое схлопывает последовательность в один
символ, добавь этот символ в предикат — иначе сломается идемпотентность соседей.

**Состояние сканера живёт сквозь текстовые сегменты.** Стек уровней кавычек и
последний выведенный символ создаются один раз на документ. Без этого кавычка
вокруг ссылки выходила двумя открывающими, а `<b>А</b>- б` получал тире прямой
речи, которого в тексте нет. Это включающая правка для всей группы правил
`common/html/*` и `ru/optalign/*` — теперь она есть.

## Что осталось и почему это важно

**Состояние фазы `Bind` через сегменты не протянуто.** Стек кавычек и левый
контекст — да, начало слова — нет. Слово, разорванное тегом (`<b>сло</b>во`), для
словарных правил остаётся двумя словами. Правила неразрывных пробелов из полного
набора упрутся в это первыми.

**Предел длины результата проверяется посегментно, а не на документ.** В
HTML-режиме каждый текстовый сегмент получает свой буфер со своим пределом, то
есть документ из многих сегментов может суммарно превысить заявленный предел.
Гарантия 2 спецификации обещает исключение вместо исчерпания памяти — сейчас она
держится лишь потому, что вход обычно из одного-двух сегментов. При объединении
фаз в один сквозной буфер это надо не потерять, а лучше сразу сделать один буфер
с одним пределом на документ.

**Правила `ru/punctuation/ano` и `ru/typo/switchingKeyboardLayout`
зарегистрированы, но не реализованы.** Их XML-комментарии честно об этом говорят;
при реализации комментарии надо поправить.

**Пресеты `Lebedev`, `Gost` и `Typograf` пока совпадают с `Default`.** Их
расхождения появятся вместе с правилами: ГОСТ 14.3 требует диапазон дат без
отбивки, практика веба ставит неразрывный пробел. Комментарии тоже надо будет
поправить.

**Узкий неразрывный пробел U+202F помечен невидимым, но отсутствует в таблице
сущностей.** Пока его никто не производит. Он появится с правилами знака номера и
параграфа (ГОСТ 16.4). Стандартного буквенного имени сущности у него нет — решено:
выводится числовым кодом `&#8239;`, см. план 2a, задача 8.

## Производительность: порядок работ

Диагностика показала, что пустой набор правил стоит 77,5 % времени полного
прогона. Платим за сегментацию разметки, три буфера на каждый текстовый сегмент и
копирование между ними, а не за сами правила.

Два следствия:

- девяносто пять новых правил почти бесплатны — оптимизировать перед планом 2
  нечего;
- если оптимизация когда-нибудь понадобится, первый кандидат — объединение фаз
  `Scan` и `Bind` в один проход с одним буфером, а не ускорение правил.

## Известные мелочи, сознательно отложенные

| Где | Что | Почему не блокирует |
|---|---|---|
| `CharBuffer` | удвоение ёмкости может переполниться при экстремальном запросе | недостижимо на входах любого реалистичного размера |
| `CharBuffer` | отрицательный предел длины молча означает «без ограничения» | предел задаётся кодом, а не пользовательским вводом |
| `EntityTable` | окно поиска точки с запятой задано числом, не связанным с длиной самого длинного имени | запас есть; сломается только при добавлении длинного имени |
| `MarkupScanner` | незакрытая кавычка в атрибуте поглощает остаток входа одним сегментом разметки | байты не портятся, разметка выходит как есть |
| `TextScanner` | `(раз,)` даёт `(раз, )` — пробел ставится перед закрывающей скобкой | закрывающая скобка не входит в класс знаков препинания |
| `TextScanner` | `3,14,15` не разбирается: эвристика «сосед-цифра» не отличает десятичную запятую от перечисления | требует контекста шире одного символа |
| `WordBinder` | короткое слово в конце входа связывается неразрывным пробелом ни с чем | косметика, видна только на обрезанных входах |
| Тесты | нет случаев на регистр тегов, на разбор имени правила из null, на кавычку сразу после двоеточия | поведение проверено вручную и корректно |

## Структура репозитория: чего ещё нет

Спецификация, раздел 10, описывает целевую структуру. Из неё пока отсутствуют:
`tests/Typographer.Corpus/` с парами эталонных файлов (корпус живёт в коде),
`tests/Typographer.Oracle/` со сверкой с веб-сервисом Лебедева, генерируемый
`docs/rules.md` с тестом на расхождение с кодом, и остальные документы `docs/`.
Всё это — содержание планов 3 и 5.
